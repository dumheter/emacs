# Agent Guidelines for .emacs.d

These instructions apply to the entire repository.

## Repository Layout

- `init.el` is the main configuration and owns package setup, global settings,
  keybindings, hooks, and small personal helper functions.
- `treesit-utils.el` is a local library for C++ symbol discovery with tree-sitter.
- `symbols-server.el` is a local client for the external `symbols` executable.
- `snippets/` contains tracked yasnippet templates.
- `dictionary/` contains the tracked Hunspell dictionary.
- `custom.el` is generated by Emacs Custom and loaded through `custom-file`.
  Do not edit or commit it unless the user explicitly asks for a Custom change.
- Runtime state such as `.cache/`, `elpa/`, `eln-cache/`, `history`, `recentf`,
  Projectile data, `tramp`, `transient/`, and server files is not source code.
  Do not edit, delete, or commit it as part of configuration work.

## Emacs Lisp Style

- Follow standard Emacs Lisp conventions and preserve the surrounding style.
  Use 2-space indentation for new code; do not reformat unrelated code.
- Preserve existing line endings. Git stores LF, while Windows checkouts commonly
  use CRLF; do not normalize whole files as a side effect.
- Use `;;` for full-line comments and `;` for short inline comments. Prefer clear
  names and docstrings over explanatory comments.
- Personal helpers in `init.el` should use the `my-` prefix. Symbols in local
  libraries should use their feature prefix (`treesit-utils-` or
  `symbols-server-`), with `--` for private implementation details.
- User-facing commands must have docstrings and `(interactive)`.
- Keep machine-specific behavior guarded by `system-type`, `system-name`, or
  feature/executable checks. Do not turn DICE-only configuration into a global
  requirement.

## Package and Configuration Conventions

- Configure packages in `init.el` with `use-package`. Use `:ensure nil` for
  built-in packages and local libraries.
- Put settings needed before package loading in `:init`; put code requiring the
  loaded package in `:config`.
- Prefer `:hook` and `:bind`/`:bind-keymap` in `use-package` declarations.
  Direct `add-hook` or keymap mutation is acceptable when the hook or map is
  created dynamically or belongs to local implementation code.
- Group related commands under a custom keymap when adding a command family,
  following `my-lsp-bridge-keymap` and `my-gptel-keymap`.
- Standalone local libraries should keep a package header, lexical binding,
  `;;; Commentary:`, `;;; Code:`, explicit `require` forms, a matching
  `(provide 'feature)`, and the standard footer.
- Never embed API keys, tokens, or machine credentials. Read secrets from the
  environment, as the gptel configuration does for `ZAI_API_KEY`.

## Important Integrations

- Packages come from GNU ELPA, Org ELPA, and MELPA through
  `package.el`; `use-package-always-ensure` installs non-built-in packages.
- Completion uses Vertico, Consult, Orderless, and Savehist.
- Project discovery and persistent indexing use Projectile.
- LSP uses the external `~/lsp-bridge` checkout.
- C++ symbol lookup primarily uses the external `symbols` executable through
  `symbols-server.el`; `treesit-utils.el` remains the in-process fallback.
- AI configuration uses gptel, with GitHub Copilot or LM Studio selected by
  machine, and enables `copilot-mode` only on DICE machines.
- EditorConfig is built into Emacs 30.1+ here. Preserve the custom advice that
  lets Emacs auto-detect existing line endings.

## Validation

- There is no automated test suite. Run a non-loading syntax check for every
  changed Emacs Lisp file:

  ```powershell
  emacs --batch -Q --eval "(progn (find-file \"FILE\") (check-parens))"
  ```

- For changes to `init.el`, also start or reload the configuration in Emacs and
  exercise the affected command or package manually. Do not use a full batch
  load as the default check: startup may refresh package archives, install
  packages, start the Emacs server, or invoke machine-specific integrations.
- For `symbols-server.el` changes, verify behavior with the external `symbols`
  executable when available. For `treesit-utils.el`, verify with the C++ grammar
  installed.
